## 结果解释边界

1. **这是已有标签 oracle 的离线重放。** PKU 和 HelpSteer2 主要提供人工偏好或评分，是 LLM judge 请求的代理任务；UltraFeedback 提供已有 GPT-4 反馈。本轮没有执行新的固定 LLM judge，也没有训练策略模型。命中率表示重放中的 judge 调用避免比例，不能当作真实训练加速比；`replay_seconds_excluding_embedding` 只是本地重放耗时。
2. **抽样与生产流量不同。** 正式输入采用跨全数据集的系统页面抽样，再比较来源顺序与 seed=42 随机顺序。UltraFeedback 的 500 个原题覆盖五个来源，各 100 题，展开后排除 83 个不完整标签请求。它不是 IID 抽样，也不是在线策略的训练轨迹；完整案例筛选还可能引入选择偏差。
3. **完整请求 embedding 是本次自定义适配。** BGE-small-en-v1.5 对完整 canonical JSON 按 480 tokens 分块、归一化 CLS、按 token 数加权平均后再归一化，不截断。它未保留严格字段匹配约束，长候选权重更大，跨块关系或少量关键 token 差异可能丢失，不能称作 vCache 论文原始 embedding 配置。
4. **冷启动与反馈时序影响命中。** 单 pass、空缓存、容量大于工作负载、动态即时反馈仅覆盖该设置。官方每条缓存包含两条伪观测，还需至少四条真实观测才进入动态决策；短流中的低命中不能直接外推长期效果。同步 drain 也不代表生产异步并发表现。
5. **报告命中与错误的两个分母。** 同时报 `hits/N`、错误命中数、命中内标签一致率以及错误命中数/N。动态参数 δ 不等同于实测的命中内错误率，更不能仅凭参数值宣称误差保证。零命中时一致率为 NA；少量命中的零错误不代表零风险。
6. **标签相同不代表判断过程可复用。** PKU 的胜者编号具有候选坐标含义；多维精确相等也受标签维数和分布影响。结合多数类占比、随机标签一致率参考及各维误差理解结果。解释文本、判断理由、在线奖励相关性与下游训练质量仍需另行评估。
